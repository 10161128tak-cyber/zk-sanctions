# OFAC SDN リスト：デジタル通貨アドレスの更新頻度（2026-09-25 集計）

## データ
- 出典: [0xB10C/ofac-sanctioned-digital-currency-addresses](https://github.com/0xB10C/ofac-sanctioned-digital-currency-addresses) の `lists` ブランチ（commit c8ab99b, 2026-09-10 時点）。OFAC の SDN リストを毎日取得し、デジタル通貨アドレスに変化があった日だけコミットしている。
- 対象期間: 毎日の取得が始まった 2022-09-15 〜 2026-09-10（約4年）。
- 集計結果: `data/ofac_crypto_updates.csv`（日付・追加数・削除数・EVM系チェーンの追加数）。再集計は `data/ofac_crypto_updates.py`。
- 注意: 「アドレスに変化があった日」の粒度は1日。SDN リスト全体（人名・団体など）はもっと頻繁に更新されるが、アドレスに関係しない更新は含めていない。

## 結果
| 指標 | 値 |
|---|---|
| 現在のアドレス数（全チェーン） | 1,053（うち ETH 120） |
| 更新があった日数 | 59日（4年間） / 直近12か月で19日 |
| 更新の間隔 | 平均25日、中央値17日（最短1日、最長87日） |
| 1回あたりの追加数 | 中央値4件、最大134件（2026-07-02） |
| 削除 | ほとんどなし。例外は 2025-03-22 の90件削除（Tornado Cash の指定解除） |

- 更新は**まれで、固まって起きる**（2022-11-09/10、2026-07-14/15 のように連日の更新がある）。ポアソン過程という仮定は粗い近似にとどまる。
- リストの規模は約1,000件なので、Merkle tree は深さ11で足りる。深さ20は OFAC 単独では過剰で、複数のリストを統合する場合の想定になる。

## 失効率の見積もり（最新のみ方式, λ = 19回/年）
| 証明を作ってから提出までの遅延 L | 失効率 1 − e^(−λL) |
|---|---|
| 10分 | 0.036% |
| 1時間 | 0.22% |
| 1日 | 5.1% |
| 7日（楽観的ロールアップからの引き出し期間） | 30% |

## 示唆
- 通常のオンチェーン送金（L が数分）なら、OFAC 単独では**最新のみ方式（Δ≈0）で十分**で、Δ の問題はほぼ生じない。
- 一方、**L が日単位になる経路**（L2 からの引き出し、クロスチェーン送金、事前に作っておく証明など）では、最新のみ方式だと数%〜30%の証明が失効する。ここで猶予を与えると Δ が日単位に広がり、「掲載直前に資金を動かす」攻撃の窓になる。
- → 研究の主な想定場面は「**提出までの遅延が長い経路**」にするのが、実データから見て最も筋がよい。
- 追加で調べたいこと: OFAC の公表から、各事業者のリストに反映されるまでの遅延（投稿の遅れ）の実態。Chainalysis などのオラクル（オンチェーンの制裁リスト）の更新遅延。
