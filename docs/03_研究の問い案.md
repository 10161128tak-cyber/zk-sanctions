# 研究の問い：1文の案

現状の仮の問い:
> 制裁リストが更新されたとき、古いリストで作った非掲載証明が使える期間（猶予期間Δ）を攻撃者に悪用されない方式を、実用的なコストで実現できるか。

今週の調査で分かったこと（02, circom-poc）を踏まえ、焦点の異なる案を5つ出す。

## 案1（定義を主役にする）
**リスト掲載から Δ 時間後にはどの非掲載証明も受理されないことを保証する安全性を定義し、その Δ を小さくしても証明者と検証者のコストがほとんど増えない方式を構成できるか。**
- 強み: 「Δ を明示した定義」「提案方式」「評価」の3点がそのまま論文の章立てになる。元の問いに最も近い。

## 案2（既存実装の脆弱性から入る）
**Tornado Cash や Semaphore が採用する「直近 N 個／T 時間のルートを許容する」設計を非掲載証明に流用すると、どの程度の攻撃窓が生じ、それを可用性を損なわずに閉じられるか。**
- 強み: 今回のPoCで攻撃を再現済みなので動機付けが具体的。実装寄りの研究に向く。

## 案3（トレードオフの定量化を主役にする）
**非掲載証明の猶予期間 Δ と、証明の作り直し・リスト更新・検証のコストとの間のトレードオフを、既存方式と提案方式で定量化し、Δ の運用上の下限を示せるか。**
- 強み: 事業者・規制当局の運用ルールの根拠という社会的価値に直結する。評価中心なので修士研究の規模に合わせやすい。

## 案4（差分証明に絞る）
**古いリストで作った非掲載証明に、更新差分についての小さな追加証明を組み合わせることで、リスト更新のたびに証明全体を作り直すことなく Δ をほぼ 0 にできるか。**
- 強み: 提案方式の中身が明確で、新規性の核が1点に絞れる。Privacy Pools の ASP が「最新ルートのみ」で証明が失効しやすい問題への直接の解答になる。

## 案5（失効研究の持ち込み）
**匿名クレデンシャルの失効技術（動的アキュムレータ等）を制裁リスト非掲載証明に適用したとき、猶予期間 Δ を明示した安全性をどの程度のコストで達成できるか。**
- 強み: 「失効研究がステーブルコインの文脈に持ち込まれていない」という着眼点を前面に出せる。理論寄りの研究に向く。

## おすすめ
**案1を主の問いにし、案4を提案方式の方向性として添える**のがよいと考える。
- 案1は定義・方式・実装・評価を一つの問いで束ねられ、投稿先（SCIS/CSS → FC 系ワークショップ）の論文構成に素直につながる。
- 案4の「差分だけ追加で証明する」は、今回の Indexed Merkle tree の PoC を拡張すれば早い段階で試作できる（更新差分に含まれる各値について「x と等しくない」ことを示すだけで済む可能性がある）。
- 研究段階が修士で実装寄りなら案3、博士で理論寄りなら案5を主にする選択もある。
